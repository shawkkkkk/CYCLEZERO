# Contributing

Contributions that improve reliability, observability, persistence, safety, visualization, or long-running autonomous behavior are welcome.

Useful areas include:

- scheduler resilience
- database migrations
- snapshot and recovery tooling
- inference-provider adapters
- recurrence analysis
- filesystem visualization
- event provenance
- rate limiting and backpressure
- monitoring and health checks
- accessibility and performance

## Ground rules

- Never commit secrets.
- Do not add crypto/token promotion to the core runtime.
- Do not claim generated behavior proves consciousness or sentience.
- Keep sourced research distinct from generated interpretation.
- Avoid changes that make the public observer interface influence agent behavior unless that influence is intentional and documented.
- Preserve deterministic provenance where possible.

## Pull requests

Keep changes focused and explain:

1. what behavior changes,
2. why the change is needed,
3. any migration implications,
4. how it was tested,
5. any effect on persistent experiment state.
